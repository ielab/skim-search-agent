# Token efficiency: paired significance test (full method vs BM25 baseline)

Backs the paper's efficiency claim with the same paired-test rigor the accuracy comparisons get in `comparison_result.md`: full method (`agent_research_bql_dense_snip`, comparison_result.md's **bql+dense+snip fetch**) vs the BM25 search-and-visit baseline (`agent_research_bm25`, comparison_result.md's **SERP bm25 [BASELINE]**), paired on shared `instance_id`s within each dataset.

Statistical test: scipy.stats.wilcoxon (v1.15.3) used for the paired signed-rank test. A paired t-test (scipy.stats.ttest_rel) is reported alongside as a secondary sanity check only — per-episode token counts are right-skewed / non-normal, so the Wilcoxon signed-rank test is primary, not the t-test.

Generated by `analysis/token_efficiency.py` (`PYTHONPATH=. envs/bin/python analysis/token_efficiency.py`).

- On **musique_structured**, the method uses 51% fewer distinct (count-once) tokens per instance than the BM25 baseline (21.3k vs 43.3k), a paired reduction significant at p=1.85e-212 (Wilcoxon signed-rank, n=2409); the accuracy delta on this dataset is Δjudge=+2.2 (p=0.0123), ΔEM=+2.7 (p=0.00073).

- The token reduction is a paired win on all three datasets (all Wilcoxon p < 0.05: 1.45e-33, 2.09e-101, 1.85e-212), so on the one dataset where the accuracy comparison is a statistical tie (browsecomp_plus_structured, Δjudge/ΔEM not significant vs the BM25 baseline), the honest framing is a same-accuracy-lower-cost result, not a null result.
- The method makes more LLM calls per instance than the baseline on the two wikipedia-derived datasets (hotpotqa_structured, musique_structured) — this is reported alongside the token win rather than obscured by it; the efficiency claim is about total context volume (tokens), not call count.
